The repository's earlier provisioning notes list these tables: `app_users`, `user_profiles`, `kyc_cases`, `financial_accounts`, `ledger_accounts`, `ledger_transactions`, `ledger_entries`, `payment_requests`, `support_tickets` and `audit_events`. These notes are not a live schema inspection; configure `DATABASE_URL` and verify the actual database before relying on any operation.

The application introspects columns in the active PostgreSQL schema at runtime and only writes through recognized fields. It performs no automatic migrations and does not create, alter, or delete tables or records. User profiles and the KYC, payment request, support, and audit workflows require compatible existing columns. Product persistence expects an `investment_products` table, which is not listed in the provisioning notes; product creation remains unavailable until its presence and schema are verified or an additive migration is separately approved.

`/api/health/database` performs a read-only `SELECT 1` health check and never returns connection details. A configured connection is not considered healthy until that query succeeds. Local JSON storage is permitted only outside production; a configured database error never triggers a local fallback. Real-money transfer and investment execution remain disabled.
